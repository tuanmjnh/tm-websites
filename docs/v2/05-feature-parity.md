### WEB-08.c — listings as structured data (landed 2026-11-11)

- Helper `buildItemListJsonLd(baseUrl, entries, { name })` in `tm-shared/packages/flow-utils/src/seo.ts` publishes the rows a listing already renders as an `ItemList`: a row without a label or without a link is dropped, a repeated URL is kept once, positions are 1..n, `numberOfItems` matches what was published, and the list stops at 50 rows so a "load more" listing cannot grow the payload without bound. An empty list returns `null`, so nothing publishes an `ItemList` with no rows.
- Wired into seven pages next to the block they already carried: the catalog listing, a catalog category landing, the category index, the post listing, a tag landing, the content category index and a content category landing. Each block is a separate script with `key: 'ld-items'`, so it sits next to `BreadcrumbList`, `CollectionPage`, `Product` and `Article` instead of replacing them.
- Only the view its canonical URL describes is published: the catalog emits nothing for a filtered or paged view (`/products?q=`, `?page=2`), the post listing emits nothing for a search/tag/category view, and a category landing emits nothing past page one, so a crawler never caches a filtered list as the catalog.
- Evidence (unit): `pnpm test:web-site` → 18 checks, 3 of them new — ordered rows with `name`/`numberOfItems`/absolute URLs, unusable rows and a repeated URL dropped with an empty list returning `null`, and the 50-row cap.
- Evidence (HTTP `:4006`, real `sen-tuan` data): `/products` → `ItemList` 12 rows named `Sản phẩm` with absolute product URLs; `/categories` → 50 rows named `Danh mục` (the 67-category tree is capped); `/bai-viet` → 1 row (`Giới thiệu Sen Tuấn`); `/tag/about` → `BreadcrumbList + ItemList` (1 row); `/categories/chan-ga-goi-dem-bo-chan-ga-bo-thuong` → `CollectionPage + BreadcrumbList + ItemList` (8 rows). `/products?page=2`, `/products?q=bo` and `/tag/huong-dan` (no posts) published no `ItemList`; `/danh-muc` kept only its breadcrumb because this store has no content categories.
- `pnpm typecheck` and `pnpm lint` pass for both slices.
- Limits: a row carries a name and a URL only (no price, image or `datePublished`), a category index over 50 categories is truncated rather than paginated, and a content row links the record's stored `/pages/<slug>` path exactly as the card does while the record's own canonical is still the short `/<slug>` form.

### WEB-01 — latest content on the home page (landed 2026-11-11)

- Page: `tm-shared/nuxt-layers/web-base/app/pages/index.vue` grew a "Bài viết mới" section between the newest products and the category strip. It renders through the shared `WebContentList` card grid, so the home page shows exactly what `/bai-viet` shows: title, teaser, tags, date and the same link.
- Reader: one `useAsyncData` call to `GET /api/public/content?type=post&locale=<ui locale>&limit=3`, keyed by locale and watched on locale change. No new route, contract or server code — the public reader already enforces published-only, started-window, site scoping and the field allowlist.
- States: the section is rendered only when the reader returned posts, so a store with no published content shows no empty section rather than a placeholder, and a reader failure hides the section instead of printing an error block on a marketing page. Nothing is invented: no counters, no fake "trending"/"sale" labels.
- i18n: `home.posts.{title,subtitle,viewAll}` in both locales, `{name}`-style placeholders only.
