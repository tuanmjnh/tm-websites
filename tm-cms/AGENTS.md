# AGENTS.md — TM CMS (Customer Admin Suite)

Guidance and standards for AI coding agents working in this repository.

## 1. Project Overview & Architecture

- **Application Type**: Nuxt 4 SPA (`ssr: false`) + Nitro API BFF.
- **Layers**: Extends `@tm/nuxt-layer-cms-base` (which inherits core, api-base, config-base, design-system).
- **Design Language**: Linear Flat Glassmorphism & Bento UI.
- **Micro-Radius Scale**: Strict compact radius: `2px`, `4px`, `6px`, `8px`, `10px` (`--ui-radius: 6px` default). Never use rounded-2xl or rounded-3xl.
- **Backdrop**: Ambient mesh backdrop (`.udmt-backdrop`) with translucent glass panels (`.panel`, `.bento-card`).
- **Identity & Central IAM**: Connects to TM Hub via satellite model using `useHub()` and Nitro BFF proxy (`/api/auth/*`).
- **Centralized Customer Config**: Defined in `customer.config.ts` and loaded into `appConfig.customer`.

## 2. Core Coding Standards

### 2.1. BasePage Rule
- Every page view in `app/pages/` MUST wrap its template in `<CmsBasePage :title="..." :description="...">`.
- Place header action buttons (Create, Refresh, Filter) in `<template #right>`.
- Responsive action dock: Actions in `#right` automatically mirror to a sticky mobile bottom dock on small screens.

### 2.2. Button Variants
- **Primary Action** (Save, Create, Confirm): `color="primary" variant="soft"`
- **Secondary / Close / Cancel**: `color="neutral" variant="ghost"`
- **Destructive**: `color="error" variant="soft"`

### 2.3. Triple-State UI Rule
Every data view must support:
1. Loading state (Skeleton shimmer with `animate-pulse` and micro rounded corners).
2. Empty state (Dashed card with icon + 1-line guidance).
3. Error state (Inline banner with retry trigger).

### 2.4. Nuxt 4 Directory Structure & Path Aliases Standard
According to official Nuxt 4 documentation (nuxt.com/docs/4.x/api/nuxt-config), frontend code is separated into the `app/` directory (`srcDir`):
- `~/` or `@/`: Points to `<rootDir>/app` (`srcDir`). Internal frontend application files (components, composables, pages, layouts, assets, app-only utils/types).
- `~~/` or `@@/`: Points to `<rootDir>` (Root Project). Files located at project root outside `app/` (e.g. `~~/config/...`, `~~/scripts/...`, `~~/layers/...`). Never use `~~/app/...`.
- `#shared/`: Points to `<rootDir>/shared`. Code, utilities, constants, and TypeScript types shared across BOTH App (Frontend) and Nitro Server (Backend) (e.g. `#shared/types/...`, `#shared/utils/...`). Never use relative traversal like `../../shared` or `~/../shared`.
- `#server/`: Points to `<rootDir>/server`. Internal Nitro Server files (services, modules, database, server-only utils/types). Used strictly within `server/`. ALWAYS prefer `#server/...` over fragile deep relative imports like `../../../../modules/...` or `../../../../utils/...` inside `server/api/` or `server/modules/`.
- `#imports`, `#app`, `#build`: Points to `<rootDir>/.nuxt/...`. Virtual modules and build artifacts generated by Nuxt.

**Strict Architectural Boundaries**:
1. NEVER use `~/server/...` or `@/server/...` (since `~/` points to `app/`, this looks in `app/server`).
2. Frontend (`app/`) MUST NEVER import from `server/` (no `~~/server/...`, `#server/...`, or relative paths into `server/`).
3. Server (`server/`) MUST NEVER import from `app/` (no `~~/app/...` or `~/...`).
4. Server API routes and modules MUST use `#server/...` (e.g. `#server/modules/...`, `#server/utils/...`, `#server/config`) instead of multi-level relative traversals (`../../../../`).
5. Any shared type, contract, validation schema, or utility MUST live in `shared/` and be imported via `#shared/...`.
6. App types in `app/types/` (`~/types/...`), server types in `server/types/` (`#server/types/...`), shared types in `shared/types/` (`#shared/types/...`). NO root-level `types/` folder.

### 2.5. Customer Layers
Customer-specific customizations (such as `sentuan-cms`, `bag-post-cms`, `thanh-tung`, `hoang-vi`) extend this base CMS by adding their layer in `nuxt.config.ts`:
```ts
extends: [
  '../tm-shared/packages/nuxt-layer-cms-base',
  '../tm-shared/packages/customer-layers/cms/sentuan-cms'
]
```
